📘 Guia de Uso

Manual completo da SAP Support Investigation Tool — como criar cases, documentar investigações, usar IA para sugestões e exportar resultados.

Visão Geral

A ferramenta é dividida em duas telas principais:

🗂 index.html

Lista de Cases — tela inicial. Exibe todos os cases salvos em tabela, permite criar novos, importar arquivos e pesquisar.

🔬 CASE_HANDLING.html

Editor de Case — tela de investigação. Sidebar com steps à esquerda, editor de blocos de conteúdo à direita, IA integrada.

Todos os dados são salvos localmente no navegador (localStorage). Nada é enviado a um servidor externo, exceto as chamadas à IA (que passam pelo proxy local na porta 3000).

💡 Dica: O servidor Node.js (server.js) deve estar rodando na porta 3000 para que a IA e os exports funcionem. Inicie com node server.js no terminal.

Início Rápido

  1. Inicie o servidor

    Abra o terminal na pasta do projeto e execute node server.js. Acesse http://localhost:3000 no navegador.

  2. Crie um novo case

    Na tela inicial, clique em ＋ New Case. Você será levado ao editor.

  3. Preencha os metadados

    No painel esquerdo, informe o Case ID, Customer, ambiente, banco de dados, arquitetura e versão afetada.

  4. Descreva o Symptom e o Repro

    Descreva o que o cliente observa no campo Symptom e os passos para reproduzir em Steps to Reproduce.

  5. Adicione Troubleshooting Steps

    Clique em ＋ Step para criar o primeiro passo de investigação e adicione blocos de conteúdo.

  6. Salve com Ctrl+S

    O case é salvo automaticamente a cada mudança, mas você pode forçar com Ctrl+S.

Ações disponíveis

  • Abrir case: Clique em qualquer linha da tabela para abrir o case no editor.
  • Deletar case: Passe o mouse sobre a linha — um botão ✕ aparece à direita. Clique nele e confirme.
  • Ordenar: Clique nos cabeçalhos das colunas para ordenar por Case ID, Cliente ou data.
  • Buscar: Use o campo de busca no topo para filtrar por ID ou nome do cliente.
  • Importar: Clique em ⬆ Import ou arraste um arquivo .zip ou .xml para a área de drop na parte inferior da tela.

Metadados do Case

No editor de case, o painel lateral esquerdo contém os metadados. Eles aparecem em todos os exports e são usados como contexto pela IA.

💡 Recolher/expandir: O painel de metadados pode ser recolhido clicando no cabeçalho Case / Incident na sidebar. Quando recolhido, o Case ID é exibido como resumo para economizar espaço vertical.

Campos disponíveis

  • Case / Incident — identificador único (ex.: 12345678)
  • Customer — nome do cliente
  • Environment — PRD, UAT, TST, DEV, SBOX
  • DB — HANA, Oracle
  • Architecture — K8s, Legacy
  • Affects Version — versão do produto afetada (ex.: 2311)
  • Symptom — descrição do problema com bullet automático ao pressionar Enter
  • Steps to Reproduce — numeração automática ao pressionar Enter
💡 Auto-save: Qualquer alteração salva automaticamente o case no localStorage.

Symptom & Steps to Reproduce

Dois campos de texto livre no painel lateral, abaixo dos metadados. São considerados em todas as chamadas de IA (salvo configuração contrária em ⚙ Prompts).

🩺 Symptom

Descreva o que o cliente observa. Pressione Enter para adicionar um novo item — o bullet • é inserido automaticamente.

• Report does not load
• Error message: HTTP 500
• Only affects user XPTO

🔁 Steps to Reproduce

Liste os passos para reproduzir o problema. Pressione Enter — o próximo número é inserido automaticamente.

1. Log in as user XPTO
2. Navigate to Reporting
3. Click Generate Report

Troubleshooting Steps

Os Troubleshooting Steps são a espinha dorsal da investigação. Cada step representa uma ação, verificação ou descoberta.

  1. Criar um step

    Clique em ＋ Step no cabeçalho da seção de steps na sidebar. Um novo step "New Troubleshooting Step" aparece.

  2. Renomear o step

    No editor à direita, clique no campo de título e escreva um nome descritivo, ex.: "Check HANA indexserver logs".

  3. Definir o tipo de finding

    Selecione no dropdown ao lado do título:

    ℹ Info 🔎 Clue ⚡ Highlight 🎯 Root Cause
  4. Adicionar blocos de conteúdo

    Na área inferior do editor, escolha o tipo de bloco e clique para adicionar. Veja a seção Blocos de Conteúdo para detalhes.

  5. Linkar steps relacionados

    Clique em 🔗 no cabeçalho do step para abrir o modal de links. Selecione outros steps que se relacionam com este. Eles aparecem no topo do step como chips clicáveis.

Minimizar o editor do step

O editor de cada step pode ser minimizado clicando no botão ▾ no canto superior direito do cabeçalho. Isso recolhe o conteúdo e libera espaço visual, deixando apenas o cabeçalho com título e tipo de finding visíveis.

Troubleshooting Step Groups

Agrupe steps relacionados para organizar a investigação por área (ex.: "Database", "Application Server", "Network").

  1. Criar um grupo

    Clique em ＋ Grupo no cabeçalho da seção de steps na sidebar. Digite o nome do grupo quando solicitado.

  2. Adicionar step ao grupo

    Com um step selecionado, use o dropdown de grupo no cabeçalho do editor (ao lado do tipo de finding) para mover o step para um grupo. Ou clique no ＋ ao lado do grupo na sidebar para criar um step diretamente dentro dele.

  3. Renomear o grupo

    Clique diretamente no título do grupo na sidebar para editá-lo. Pressione Enter ou clique fora para confirmar.

  4. Recolher/expandir o grupo

    Clique no ícone ▾ ao lado do nome do grupo para recolhê-lo. Clique novamente para expandir.

  5. Deletar o grupo

    Clique no ícone 🗑 ao lado do grupo. Os steps do grupo são mantidos, mas ficam sem grupo (desassociados).

Reordenar Steps e Grupos

Tanto steps quanto grupos podem ser reordenados diretamente pela sidebar usando os botões de seta.

↕

Botões ▲ ▼ aparecem à direita de cada step e grupo na sidebar. Clique para mover para cima ou para baixo.

Steps dentro de um grupo só se movem entre os outros steps do mesmo grupo. Grupos se movem como um bloco inteiro — todos os seus steps se movem junto.

💡 Ordem importa: A numeração dos steps (S1, S2…) é calculada a partir da ordem de exibição: steps sem grupo primeiro, depois os grupos em ordem, com os steps dentro de cada grupo.

Referências @ID entre Steps

Cada step possui um identificador curto visível na sidebar e no cabeçalho do editor (@S1, @S2, etc.). Você pode referenciar steps em qualquer bloco de texto.

Como usar

  1. Digite @ em qualquer bloco de texto

    Um popup de autocomplete aparece listando os steps disponíveis.

  2. Selecione o step

    Use ↑ ↓ para navegar no popup, Enter ou Tab para inserir, Esc para fechar.

  3. Na exportação

    O @S1 é substituído automaticamente por (refer Step S1: "título do step") em todos os exports.

Exemplo — no editor você escreve:
O erro foi identificado em @S3, após a coleta de logs descrita em @S1.
No export aparece como:
O erro foi identificado em (refer Step S3: "Analyze indexserver crash"), após a coleta de logs descrita em (refer Step S1: "Collect HANA logs").

📝 Blocos de Conteúdo — Text & Highlight

Cada step pode conter múltiplos blocos de conteúdo. Clique nos botões da barra Add Block na parte inferior do editor para adicionar.

📝 Text 🗄 SQL Query 📋 SQL Result 📋 Log 📊 Table 🖼 Image 🎬 Video 📎 Attachment ⚡ Highlight

📝 Text

Editor de texto rico (WYSIWYG) com barra de ferramentas. Suporta negrito, itálico, sublinhado, tachado, código inline, blockquote, listas numeradas e com bullets. Use Tab para indentar.

⚡ Highlight

Idêntico ao bloco Text, mas com fundo destacado em âmbar. Ideal para marcar descobertas importantes. O texto no bloco Highlight aparece em amarelo claro para chamar atenção.

🗄 SQL Query

Bloco para colar queries SQL. Exibe o conteúdo em fonte monospace com cor azul claro. Não tenta formatar como tabela — apenas armazena o SQL puro.

Exemplo
SELECT TOP 100 *
FROM "_SYS_BI"."BIMC_ALL_CUBES"
WHERE SCHEMA_NAME = 'SAPABAP1'
ORDER BY CUBE_NAME;
💡 Exportação: No export de texto, o SQL Query é exportado como bloco de código ```sql.

📋 SQL Result

Bloco para colar o resultado de uma query. Detecta automaticamente se o conteúdo é CSV, TSV ou pipe-separated e exibe como tabela formatada abaixo do textarea.

  1. Cole o resultado da query

    Formatos suportados: CSV (vírgula), TSV (tab), ou pipe | (formato padrão de clientes SQL como DBeaver e HDBSQL).

  2. A tabela aparece automaticamente

    Se o conteúdo for reconhecido como tabular, uma visualização em tabela aparece abaixo do campo de texto com o badge ⊞ Table auto-detected.

⚠️ Atenção: Se o resultado vier em formato pipe | com separadores de linha como ---+---, a ferramenta ignora as linhas separadoras automaticamente. Linhas que começam com SELECT/INSERT/UPDATE são tratadas como SQL puro e não como resultado tabular.

📋 Log

Bloco para colar entradas de log (HANA trace, application log, system log, etc.). Exibe em fonte monospace com cor verde clara, facilitando a leitura.

💡 Dica: Cole apenas o trecho relevante do log. Logs muito longos são truncados a 2000 caracteres no contexto enviado à IA para evitar desperdício de tokens.

📊 Table

Bloco de tabela editável manualmente. Cole CSV/TSV/pipe no textarea — a tabela é renderizada abaixo. Diferente do SQL Result, este bloco é para dados que você quer documentar sem necessariamente ter uma query associada.

🖼 Image

Adicione capturas de tela, diagramas ou qualquer imagem ao step. Três formas de adicionar:

📋 Ctrl+V

Cole diretamente do clipboard. Funciona com screenshots (PrtScr, Snipping Tool, etc.). Funciona tanto na drop zone focada quanto globalmente se houver um bloco de imagem vazio no step ativo.

🖱 Drag & Drop

Arraste um arquivo de imagem do seu explorador de arquivos diretamente sobre a área de drop do bloco.

🗂 Clique para escolher

Clique na área de drop para abrir o seletor de arquivo. Suporta PNG, JPG, GIF e WebP.

📝 Legenda

Após inserir a imagem, um campo de texto aparece abaixo para adicionar uma legenda descritiva. A legenda aparece no export do Guide.

🎬 Video

Incorpore vídeos diretamente no step. Cole a URL no campo — YouTube e Vimeo são exibidos como player embutido; links diretos de arquivo (.mp4, .webm) usam o player nativo do navegador.

Formatos suportados

  • YouTube: https://www.youtube.com/watch?v=... ou https://youtu.be/...
  • Vimeo: https://vimeo.com/123456789
  • Arquivo direto: https://exemplo.com/video.mp4

📎 Attachment

Anexe qualquer tipo de arquivo ao step — PDF, Word, Excel, texto, imagem, vídeo, zip, etc. O arquivo é armazenado em base64 no caso.

Como adicionar

Clique na drop zone ou arraste um arquivo. Todos os tipos de arquivo são aceitos.

Preview automático

Imagens são exibidas diretamente. PDFs são exibidos em iframe embutido. Outros formatos mostram nome e tamanho do arquivo.

⬇ Download

Clique em Download para salvar o arquivo anexado localmente.

No ZIP export

Ao exportar como ZIP, imagens do bloco Image são incluídas em attachments/. Arquivos do bloco Attachment são referenciados como metadados no XML.

⚠️ Tamanho: Arquivos grandes aumentam significativamente o tamanho do localStorage. Para arquivos muito grandes (acima de alguns MB), prefira referenciar por caminho ou URL em vez de anexar.

🤖 Sugestão de Steps por IA

A IA pode sugerir os próximos passos de investigação com base no contexto atual do case e na knowledge base. O botão 🤖 fica no cabeçalho da seção de steps na sidebar.

  1. Clique em 🤖

    O modal de sugestões abre e a IA é consultada imediatamente via RAG (servidor).

  2. Aguarde as sugestões

    A IA analisa o Case ID, metadados, Symptom, Steps to Reproduce, steps já existentes e documentos da knowledge base. Em alguns segundos, apresenta uma lista de steps sugeridos com título e justificativa.

  3. Aceite ou rejeite cada sugestão

    Cada sugestão tem uma checkbox. Marque as que deseja aceitar e clique em Add selected. Steps desmarcados são registrados como rejeitados para métricas de efetividade.

  4. Marcar como editado

    Após editar um step gerado por IA, clique em ✏ Mark as edited no banner azul para indicar que o conteúdo foi adaptado.

💡 Efetividade: No tab 📦 Package, você vê estatísticas de contribuição da IA: quantos steps foram sugeridos, aceitos, editados e rejeitados, com percentual de efetividade.

🤖 Análise por IA

Na aba 🤖 AI Assist do modal de exportação, você pode gerar análises completas para o Pulse ticket.

📋 Full Analysis

Gera as quatro seções do Pulse: Internal Research, External Research, Cause e Solution/Workaround de uma vez só.

🔒 Internal Research

Só a seção interna — detalhes técnicos, sem preocupação com linguagem para cliente.

🌐 External Research

Versão sem dados internos, adequada para compartilhar com o cliente.

🎯 Cause & Solution

Foca em identificar a causa raiz e propor solução/workaround.

Você também pode clicar em Copy Prompt para copiar o prompt completo com o contexto da investigação e usar em outra ferramenta de IA manualmente.

🤖 KBA & Incident Message

📚 KBA (Knowledge Base Article)

Na aba KBA, preencha os campos manualmente ou clique em ✦ AI Auto-Fill KBA para a IA preencher automaticamente Symptom, Steps to Reproduce, Cause e Solution com base na investigação. O resultado é retornado em JSON e populado nos campos.

💬 Incident Message

Na aba Messages, escolha o público-alvo e clique em ✦ Generate with AI:

  • Technical Engineer — mensagem técnica detalhada para L2/L3
  • Developer — focada em comportamento do código, para o time de engineering
  • Swarm — resumo para sessão colaborativa de troubleshooting
  • Custom — descreva o público manualmente no campo de texto que aparece

O botão Copy Prompt gera o contexto da investigação (sem SQL/logs por padrão) formatado como prompt para uso externo.

🚨 Incident (Escalation Fields)

Na aba Incident, preencha os campos para escalonamento. Os campos são pré-populados com os metadados do case:

  • Description
  • Label
  • Customer Name
  • Tenant ID
  • Environment
  • Affects Version
  • DB
  • Architecture
  • Steps to Reproduce
  • Findings
  • What is needed from Engg Team
  • Logs (seleção por step)

Seleção de Logs: Se o case tiver blocos de Log, uma lista de checkboxes aparece permitindo selecionar quais logs incluir no escalonamento. Cada log selecionado pode receber uma descrição explicativa.

Clique em ✦ AI Generate Fields para preencher automaticamente Description, Steps to Reproduce, Findings e What is needed. Clique em Export Report para gerar o texto formatado para copiar.

📖 Guide (Geração de Guia)

A aba 📖 Guide permite gerar um guia de investigação completo e exportável. Pode ser gerado automaticamente pela IA ou construído diretamente dos dados da investigação.

Opções do Guide

  • Include screenshots & images — inclui as imagens dos steps no guia
  • Include SQL queries & results — inclui queries e resultados de SQL
  • Include log excerpts — inclui trechos de log (limitado a 800 caracteres por bloco)
  • Highlights & Root Cause steps only — filtra para mostrar apenas steps do tipo Highlight e Root Cause, excluindo Info e Clue

Botões de ação

✦ AI Generate Guide

A IA recebe o contexto da investigação e gera um guia em HTML estruturado com: Summary, Key Findings, Root Cause, Resolution Steps e Preventive Measures.

🖨 Export as PDF

Usa o print do navegador para gerar um PDF com formatação limpa (fundo branco, tipografia adequada para impressão).

⬇ Download HTML

Baixa o guia como arquivo .html standalone autocontido — pode ser aberto em qualquer navegador sem o servidor.

📋 Copy Text

Copia o conteúdo do guia como texto simples para a área de transferência.

💡 Dica: O guia gerado pela IA e o guia gerado dos dados são independentes. Ao clicar em AI Generate Guide, o preview mostra o resultado da IA. Ao modificar as opções de filtro, o preview retorna para o guia baseado nos dados.

📚 RAG & Knowledge Base

O sistema usa Retrieval-Augmented Generation (RAG): antes de cada chamada à IA de sugestão de steps, o servidor busca os 3 documentos mais relevantes na pasta knowledge/ e os inclui no contexto. Além disso, os agentes client-side também podem consumir documentos da knowledge base via ⚙ Prompts.

Como adicionar documentos

  1. Crie arquivos .txt, .md, .xml ou .zip

    Coloque na pasta knowledge/ do projeto. Pode ser qualquer texto: notas técnicas, KBAs, runbooks, documentação interna, exports de cases anteriores.

  2. Clique em "🔄 Re-index files" no tab Package

    O servidor gera embeddings para os novos arquivos e atualiza o knowledge_index.json. Arquivos já indexados são ignorados.

  3. Verifique o status

    O tab 📦 Package mostra quantos documentos estão indexados e lista os nomes das fontes.

Contribuição automática — Caso Resolvido

Ao clicar em ✅ Case Resolved, a skill exportada é automaticamente salva na pasta skills/ e indexada na knowledge base. Assim, cases resolvidos alimentam futuras sugestões de IA.

Você também pode clicar em 📤 Contribute this case to RAG no tab Package a qualquer momento para contribuir o case em andamento sem marcá-lo como resolvido.

RAG no client-side (por agente)

Os agentes de IA chamados diretamente pelo browser (AI Assist, KBA, Messages, Incident, Guide) também podem consumir documentos da knowledge base. Configure isso por agente em ⚙ Prompts → Knowledge Base (RAG).

💡 Aprendizado contínuo: Quanto mais cases resolvidos você exportar como skill, melhor e mais específica será a IA nas sugestões de próximos passos.

📦 Exportar como ZIP

Toda a investigação pode ser exportada para um arquivo portátil e reimportada depois. O tab 📦 Package é o ponto central de exportação e gestão do knowledge base.

Conteúdo do ZIP

📄 case.xml

Toda a estrutura do case: metadados, groups, steps, blocos de conteúdo, links, KBA, incident e AI metadata.

🗂 attachments/

Todas as imagens dos blocos Image como arquivos separados. Imagens são referenciadas no XML pelo nome do arquivo.

✅ Caso Resolvido — Export de Skill

Quando o case for resolvido, use o botão ✅ Case Resolved no topo da topbar para exportar as descobertas como uma Skill reutilizável.

⚠️ Pré-requisito: O case precisa ter um Case ID preenchido e pelo menos um step do tipo Clue, Highlight ou Root Cause.

O que é exportado

Um arquivo skills/case_<ID>_skill.md é gerado com:

  • Metadados do case (cliente, ambiente, banco, versão)
  • Apenas os steps com Highlight, Clue ou Root Cause — descartando steps Info sem relevância
  • Grupos preservados como seções do Markdown
  • Conteúdo de texto, SQL, logs e links de vídeo
  • Indicação de steps gerados por IA

Contribuição para RAG

O arquivo é automaticamente indexado na knowledge base. A partir deste momento, futuras investigações similares receberão sugestões baseadas neste caso resolvido.

📥 Importar Cases

Você pode importar cases exportados anteriormente de três formas:

🗂 Na lista de cases

Na tela inicial, clique em ⬆ Import ou arraste o arquivo para a área de drop na parte inferior da página.

🔬 No editor

Clique em ⬆ Import na topbar ou use o botão 🗂 Cases para abrir o modal de importação diretamente no editor.

Formatos aceitos: .zip, .xml e .json (estado bruto).

⚠️ Atenção: Se o Case ID do arquivo importado já existir no navegador, o case existente é sobrescrito com os dados do arquivo importado.
